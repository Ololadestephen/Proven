A COMMON WORKFLOW

From agreement
to a recorded outcome.

The buyer, worker and verifier each have a defined part. The payment follows the job’s recorded state.

  1. 01

    Post once

    Commit the check and format, and fund payment, checking and fees in one signature.

  2. 02

    Challenge

    Test the acceptance check against the planted fakes.

  3. 03

    Claim

    A worker claims the checked job; the board assigns that account.

  4. 04

    Deliver

    The selected worker commits the delivery hash.

  5. 05

    Verify

    Escrow requests execution through OutLayer.

  6. 06

    Settle

    Release or refund against the recorded verdict.

Only the escrow’s private callback can record a verdict. A worker message or a model’s opinion cannot release the payment.

GUARDRAILS AROUND THE HANDOFF

Defined roles.
Visible trust boundaries.

The buyer uses restricted custody. Workers use scoped keys. Fixed hashes bind the job to its check and delivery. A convenience relay can trigger calls and supply private inputs, but it cannot post the verdict.

OutLayer’s contract, registered worker keys and approved measurements remain trusted. Individual run quotes are not verified on chain, and the relay can read or withhold private inputs.

BEFORE YOU START

A few useful
questions.

The boundaries are part of the product.

What work can Proven check?

Structured data and functions in the supported verifier format, with executable acceptance conditions. Subjective judgments—such as whether an essay is good—are outside this flow.

Does an execution error count as a failed delivery?

No. A promise failure, timeout, malformed output or binding mismatch produces no verdict. It must never become a pass or fail.

What if verification never finishes?

A job without a verdict can be retried within its allowed window, then reach the existing expiry/refund path. Withheld inputs can leave an honest worker unpaid until the buyer’s refund, so relay availability remains important.

Are private inputs hidden from everyone?

No. The relay can read private plaintext and OutLayer’s keystore remains trusted. Public hashes and metadata can also reveal information, especially for predictable inputs. The guide explains the remaining privacy boundaries.

Can I use mainnet or cross-chain payouts today?

useproven.xyz is an unaudited, owner-funded mainnet deployment. The owner holds a single key that can upgrade the contracts. Access comes from the board’s buyer list. The app reads current limits from the escrow. Cross-chain payouts are not implemented; the adapter provides read-only quotes.
